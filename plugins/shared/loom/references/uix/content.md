# UIX Focus: Content

Load this when visible product copy, labels, empty states, validation, status, or help text are created or changed.

## Product Copy Rules

- Use the user's product language and locale.
- Write labels around user tasks and business objects, not implementation structures.
- Avoid internal delivery, tooling, and workflow terms in product UI.
- Avoid explaining runtime commands, verification steps, or technical stack unless the product is a developer tool and the user task requires it.
- Keep page headings concrete: name the product area or business task.
- Use one vocabulary for each business object. Do not alternate between internal entity names, API names, and user-facing labels.
- Prefer concise operational copy over onboarding paragraphs inside repeat-use products.

## User-Visible Boundary

These phrases belong in implementation notes, not normal product UI:

```text
internal workflow id, generated artifact id, delivery phase, verification command,
localhost, Docker, Gradle, npm, Prisma, Spring Boot, SQLite,
validator term, generated by agent, build passed
```

Developer tools are the exception only when those terms are the user's product domain.

## State Copy

- Loading: short and scoped to the region.
- Empty: explain the business state and next action.
- Validation: tell the user what to fix and where.
- Error: explain recovery, not stack traces.
- Business-blocking: state the domain rule and affected object.
- Success: confirm what changed and show the new status when useful.

## Controls

- Button labels should be verbs or clear commands.
- Destructive labels should name the destructive action.
- Icon-only controls require accessible labels.
- Avoid generic labels such as "Submit" when the business action is known.

Label pattern:

| Context | Better label |
| --- | --- |
| Create business record | `Create request`, `Open account`, `Add supplier` |
| Destructive action | `Close account`, `Delete draft`, `Cancel order` |
| Retry after technical error | `Retry`, `Reload list` |
| Business block | `Resolve missing approval`, `Clear holdings first` |
| Detail navigation | `View details`, `Back to list` |

## Dense UI

- Tables and badges need short, consistent status labels.
- Tooltips should clarify controls, not contain critical information that mobile users cannot access.
- Long help text belongs in a side panel, detail section, or docs route rather than inside every row.

## Copy Evidence

Evidence should cite changed files or screens that prove:

- Forbidden internal terms are absent from product UI.
- Empty, error, validation, success, and business-blocking copy exist where those states are in scope.
- Page headings and action labels use business language.
- Long messages wrap without hiding controls.
