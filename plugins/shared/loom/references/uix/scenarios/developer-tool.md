# Developer Tool UIX

Use for local tools, configuration consoles, API clients, build/deploy tools, debug panels, and engineering-facing products.

## Baseline

- Technical information may be user-facing only when the product's users are developers and the information is part of the task.
- Distinguish product runtime controls from Loom delivery notes or verification evidence.
- Prefer dense, copyable, keyboard-friendly, and stateful interfaces over decorative explanation panels.

## Required Patterns

- Commands, logs, env values, diffs, and diagnostics need copy affordances, grouping, truncation, and error recovery.
- Dangerous actions need scope, target, and consequence clarity.
- Status should separate pending, running, succeeded, failed, cancelled, and stale states.
