# Scope And Coverage

For named files, keep discovery within that file set. If a file points to a build script, provider policy, or other dependency outside scope, record the unanswered question and the specific evidence needed. Resolve linked skill companions relative to the skill directory to avoid scanning the installation repository. Record the revision when available and treat missing metadata as a limitation.

For a diff, trace changed entry points to their authorization decision and durable effects. Include unchanged callers or adapters only where they establish the effective control. For a repository review, identify which applications, workers, clients, and deployable packages are actually shipped.

For each boundary, record the principal, protected resource, allowed operation, enforcing component, and source reference. Capture assumptions about identity providers, network placement, and configuration rather than treating them as observed facts.

Track each boundary as reviewed, blocked, excluded, or pending. A folder name or search result is not proof of review. Note why a boundary does not apply and do not count an exclusion as covered. When evidence is missing, name the specific policy, deployment setting, or owner decision needed to resolve it.
